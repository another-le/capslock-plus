# 鼠标手势参考与直接移用

- Lexikos/Gestures.ahk：`Lexikos-Gestures/`，固定版本 `04dfb9269351798a9f16a1cdc0de7c67576e0560`。
- ayuanx/AutoHotKey_MouseGesture：`AutoHotKey_MouseGesture/`，固定版本 `b59e6b9355142022f53721a0a3fdc0c6badc0e04`。

两个目录是完整上游源码。项目运行不依赖桌面的参考目录，也不单独运行参考项目。

`lib/vendor/LexikosGestureEngine.ahk` 直接移用了 Lexikos 原文件从 `CancelGesture:` 到 `G_GetZone()` 结束的完整核心，保留识别循环、方向分区、连续方向去重、阈值、超时、取消、松开时补采及动作标签分发。核心只在绘制回调、实时提示和右键输入处理处做了少量适配；回归脚本会检查扣除这些适配后与上游核心完全一致。

`lib/lib_mouseGesture.ahk` 提供项目适配：设置映射、Chrome 动作、目标窗口、紫色轨迹和热键入口。Chrome 与其他应用都使用同一个可穿透分层窗口绘制连续 9 像素轨迹，绘制最多约 25 帧/秒；识别仍每 20 ms 采样。不再为每个点创建小窗口，也不加载上游托盘菜单、默认动作及全屏 GUI；上游画布关闭，避免与本项目 GUI 冲突以及旧的 32 位 GDI 句柄绘制路径。AutoHotKey_MouseGesture 保留为参考，运行时只启用一个引擎。

默认使用原版的四方向、100% 角度容差和 20 ms 采样。在启用手势的窗口中，右键按下和松开统一拦截：识别到动作才执行手势；只有没有明显移动的按下、松开会补发普通右键单击，不规则或未配置的滑动不会弹右键菜单。因此，应用原生的右键拖动操作会被手势占用；桌面、任务栏（包括托盘及隐藏图标区）、菜单和本项目设置窗口不拦截。排除规则按顶层窗口判断，文件资源管理器窗口仍可使用全局手势。项目设置映射至原版的移动阈值与释放超时。动作按完整方向组合匹配，例如 `_D_L`，不按前缀匹配。

当前 Chrome 中 `_D_R` 仅发送 `Ctrl+T` 新建标签页，显示什么页面由 Chrome 的新标签页设置决定；单独 `_D` 没有动作。非 Chrome 仅 `_D_L` 关闭窗口，其余路径不执行动作。中央动作提示在任何已捕获窗口的右键滑动达到识别阈值后显示，并在右键释放后隐藏；未配置的方向会提示“未设置动作”，不会弹出右键菜单。

直接运行 `CapsLock+.ahk`。紧急退出：`Ctrl+Alt+Shift+F12`。

回归检查：`powershell -NoProfile -ExecutionPolicy Bypass -File tests/test_mouseGestureEngine.ps1`。测试在独立临时脚本内注入采样坐标，执行原版识别循环和右键生命周期，不向用户桌面发送鼠标事件。
